# Hand-off files are checked against their owned formats before they are written

Status: accepted

interphase vendors byte-identical copies of the harness program's shared validator and of every schema it writes or reads, H11 for the interview record, H12 for the items file, and K1, K2 and K6, and checks each hand-off through that one validator: every script that writes the record or the items checks the exact value it is about to write against its owned format plus interphase's own cross-field rules, and writes nothing when either fails; every script that reads one refuses a value that fails, naming the file, the schema and each error, rather than skipping or counting around it. We chose this over checking only where another plugin reads the file, which let a fault surface stages after it was born, and over keeping interphase's own smaller validator, which could drift from the one mitosis, lighthouse and pipeline use. The trajectory store is read through K6 after removing the two fields the store itself adds, id and ts, because K6 describes the entry a caller appends, not the stored line; a store line that fails is reported and not counted, because the store is shared with callers interphase cannot fix. A schema or validator change stays a program decision made in the program's copy; the vendored copy is replaced to match, and the tests compare the two through the program's check_copies.py rather than pinning digests, so the change needs no test edit.
